# 多巴胺刷题 — 公开版规格书

多巴胺刷题是一款浏览器计算游戏，每解一道题，吉祥物的动作、画面演出与音乐都会随之增强。本书面向游玩者与家长、以及对开发、改造感兴趣的人，说明当前实现的行为。数值可能会在后续调整中变更。

## 1. 概要与设计思路

目标是让用户每天坚持做一点计算，并能确认自己相比过去的成长。基础题即使超过目标时间也可以继续，全部做对即为 100 分。没有 Game Over。

答错时显示「差一点」，可以重新作答。已获得的星、奖杯、演出不会因失败或缺勤而被收回。连续记录有补上缺席日的机制，成长对比只显示有改善的项目。奖励通过达成条件解锁，不存在通过抽签或付费获取的途径。

界面为中文（原版为日文），既支持小学生的计算练习，也适合成年人使用。以手机竖屏为主，在 PC 上也可以用鼠标、键盘操作。无需注册账号。记录按浏览器分别保存，因此不会与其他设备自动同步。

## 2. 界面与流程

### 2.1 界面一览

| 界面 | 内容与主要操作 |
| --- | --- |
| 标题 | Logo、多巴奇、我的水平、其正下方的复习、1～6 年级、技能树、奖杯、收藏、任务、日历、设置、？ |
| 游玩 | 题目、输入的格、专用数字键盘、答对数、差一点次数、时钟、多巴、连击、进度显示、静音 |
| 基础结果 | 100 分、用时、首次正确率、多巴、成长·技能·任务的结果。达成条件时的加时、重做、再来一次、返回标题的操作 |
| 最终结果 | 含加时的得分与多巴、答对数、差一点次数、任务、重做·返回标题的操作 |
| 技能树 | 前置关系、解锁·练习·大师的状态、星、生锈、技能的说明与练习、记录的部分删除 |
| 奖杯 | 按分类·系列的成就、获得日期、条件与奖励、筛选、即将获得的成就 |
| 收藏 | 已解锁演出的试看·试听、按类别固定或随机 |
| 设置 | 题量、声音、音量、动效强度、演示、全部重置 |

通常按「标题 → 基础题 → 基础结果 → 可选的加时 → 最终结果」的顺序进行。复习进行到基础结果为止。结果画面的操作按钮固定在底部，这样即使成长记录增多也能继续下一步操作。

### 2.2 首次说明与「？」帮助

首次会显示 5 页说明。顺序为玩法、我的水平、按年级、技能树、推荐使用「我的水平」的提示。点设置按钮下方的「？」，可以重新显示加上奖杯与收藏的 7 页说明。

用聚光灯照亮说明对象，必要时滚动画面。说明文字显示在独立的卡片中，多巴奇通过移动、指向与表情进行引导，不作为多巴奇的台词显示。最后会指示「我的水平」与「？」，若两者无法同时收进画面，则在卡片内显示同样的问号图标。

使用「下一步」「返回」「跳过」，以及最后的「开始！」进行操作。Enter、右方向键为下一步，左方向键为上一步，Escape 为跳过，Tab 在说明内移动焦点。点击遮罩不会关闭，说明过程中无法操作背景中的按钮。

无论看到最后还是中途跳过，都会保存为已显示。首次说明之后，按补签锤、登录奖励、奖杯通知的顺序处理。全部重置后会再次显示首次说明。演示中和部分确认用 URL 下不会自动显示。

## 3. 模式

### 3.1 我的水平

首次进行「水平测试」。按年级、前置关系的深度排序推进技能，首次答对时将该出题对象及其前置技能一并设为大师、☆1。移动幅度最初为 6，答对后取当前幅度的 1.3 倍向上取整、最大为 12，答错后取一半向下取整、最小为 1。答错后会回到最后一次首次答对位置之后的范围。做完基础题后即视为已完成测试。

之后的出题依据前置关系的深度、年级、技能定义顺序来选择。从已达到大师的末尾 6 个技能中选取复习题，复习名额为 `min(候选数, max(1, round(题量 × 0.3)))` 题。优先选择生锈的技能，其余从候选中随机选取。若没有已达到大师的技能，复习名额为 0。

其余部分按顺序循环取已解锁且未达到大师的前 4 个技能。若全部已达到大师，则从全部已达到大师的技能中选择。加时循环取未达到大师的候选中的末尾 3 个技能，若没有则取已达到大师的末尾 3 个技能。测试刚结束后的加时，从已解锁且未达到大师的开头开始选取。

### 3.2 按年级

无论解锁状态如何，都从所选年级的技能中出基础题。整体顺序由前置关系浅到深，并加入随机扰动。答题结果也会反映到常规的技能进度中。

加时的前 6 题循环取该年级技能列中第 `floor(技能数 × 0.55)` 个之后的技能。从第 7 题起切换为下一个年级开头最多 4 个技能。6 年级时继续使用本年级的后半部分。

### 3.3 练习

在技能树中选择已解锁的技能进行练习。若已达到大师，可以从说明画面开始练习。基础题使用该技能，加时从以该技能为直接前置的已解锁技能中选取。若没有对象，则继续使用同一技能。

在按年级与练习中，满足条件的时间胶囊可能会替换基础题中的 1 题。这 1 题可能超出指定的年级·技能范围。

### 3.4 复习

在把包含答错的题做到最后时，最多保存 40 道题目本身。以题目的标题与算式作为标识符去除重复。中途中断的未完成题目不会加入。

可以从标题与结果中的重做按钮开始。从已保存列表的末尾起，以设置的题量与 10 中较小的一方为上限选取。即使从结果的按钮开始，也不仅限于本局的答错题，而是使用此前留存下来的列表。

重新做时首次答对的题目会从列表中删除，再次答错的题目会保留。全部做对即为 100 分，没有加时。也会反映到常规的成长记录、技能进度、任务中。

### 3.5 演示

在设置中开启「演示」即可开始自动操作。从全部技能中选出的题目按由易到难排序，加时从 4 年级以上的技能中选取。使用常规的输入、判定与演出，也会加入答错。基础部分答错的题数上限为 `floor(题量 × 0.2)`。

依次走完基础、加时、最终结果一轮后返回标题，并解除演示。点击或按键操作也可以结束。开始后立即点击会有 600ms 的忽略时间。演示的游玩结果不会计入历史、技能进度、复习与成长统计，也不会推进任务或奖杯的获得。返回标题后的常规登录处理仍会执行。

固定选择的演出在演示中也会使用，只有设为「随机」的类别会从已解锁的收藏中选取。URL 的 `?demo` 是与该自动操作不同的功能。

## 4. 单局游玩与输入

### 4.1 基础题与加时

题量为 6、10、14 题，初始值为 10 题。基础的目标时间为 `ceil(题量 × 18 ÷ 10) × 10` 秒，6 题为 110 秒、10 题为 180 秒、14 题为 260 秒。超过后也可以继续，不会扣分。基础的用时从游玩开始到完成为止，包含题目切换。

「答对」指完成到最终作答为止的题数，「差一点」指已受理的数字对当前的格来说错误的次数。「首次答对」指包括途中输入在内从未答错而完成的题。基础的首次答对数除以题量所得比例在 0.8 以上时，可以选择加时。

加时默认 90 秒。在开始处理的时刻加上 90,000ms 与用于导入的 900ms 来设定期限。并非以保证从可首次输入的时刻起 90 秒的方式计算，题目切换过程中时钟也会继续走。确认对话框期间会暂停。时间到即确定得分，进入最终结果。未完成的题目不计得分，但已受理的正确格所增加的多巴会保留。

### 4.2 数字输入

使用专用数字键盘与 PC 的数字键逐位输入，并当场判定。没有确定答案的按钮。正确的位会保留，错误的数字会在下次输入时被替换。Backspace 是删除当前错误数字的操作，不会取消已答对的位。

在手机上会配合包含浏览器操作栏在内的显示区域，调整题目的留白与数字键盘的高度。把包含 0 与删除键的最下排放置在底部安全区域之上，画面尺寸变化时会重新计算题目的文字大小。

| 题目形式 | 输入顺序与自动显示 |
| --- | --- |
| 横式 | 从答案左侧的位开始输入 |
| 横式带余数的除法 | 按商、余数的顺序 |
| 加减法竖式 | 从最下面的位开始。自动显示进位·退位的辅助数字 |
| 乘法竖式 | 从右往左输入部分积，有多个部分积时合计也从右往左输入 |
| 除法竖式 | 按商的高位、相减后的余下部分、下一位商的顺序。积、拉下来的数字、最后的余数 0 自动显示 |
| 小数 | 自动显示小数点，只输入数字 |
| 分数 | 按分母、分子的顺序。带分数按整数部分、分母、分子的顺序 |
| 比、代数式、近似数、百分比 | 从指定空格的左侧位开始输入 |

分数按准备好的作答形式判定。3 年级的同分母分数保留原分母，接受不约分的答案。其他分数计算使用生成的最简分数·带分数形式。不是自由输入等价的其他表示再判定的方式。

### 4.3 答错与提示

错误的数字使用紫色虚线框。在同一个格答错 2 次时，若定义了应当参照的数字，则进行高亮与指向。第 3 次起显示计算过程的中间算式或乘法口诀列等提示。提示中有时会包含相当于答案的数值。

答错会使连击归 0，但不扣得分与多巴，并维持演出阶段与 BGM。为了答错音效会暂时压低 BGM，并使用弹跳感的音效与多巴奇恢复的动作。

## 5. 得分·多巴·连击

### 5.1 得分

基础完成为 100 分。设加时中已完成题目的编号从 0 开始为 `k`，则该题的加分为 `10 + 5 × k` 分。完成 `n` 道加时题目的合计得分为下式。

```text
100 + 10 × n + 5 × n × (n − 1) ÷ 2
```

5 题得 200 分、10 题得 425 分、15 题得 775 分、23 题得 1595 分、30 题得 2575 分。得分没有固定上限。不存在因连击、作答速度、「差一点」次数产生的得分倍率或扣分。

### 5.2 多巴的计算

多巴是演出用的数值，与得分不同。内部以常用对数持有数值 `L`，显示值的原值为 `10^L`。游玩开始时为 `L = 0`。

基础部分的基准曲线为 `B(f) = 2.3 × clamp(f, 0, 1)^1.15`，加时的基准曲线为 `X(n) = 2.3 + 3.0 × (1 − exp(−n / 10))`。

设基础部分的总题量为 `N`、已完成题目数从 0 开始为 `q`、当前题目的作答格数为 `m`、本次答对的格从 1 开始为 `s`，则该次输入的基准增量为 `B((q + s/m)/N) − B((q + (s−1)/m)/N)`。设加时的已完成题目数为 `k`，则每格的基准增量为 `(X(k+1) − X(k))/m`。

答对时先将连击数 `c` 加 1，再用下式反映该次输入。

```text
倍率 M(c) = 1 + (2 − 1) × min(1, max(0, c) / 20)
新的 L = min(9.08, L + max(0.003, 基准增量) × M(c))
```

10 连击为 1.5 倍、20 连击以上为 2 倍。上限为对数值 9.08，换算回原显示值正是 `10^9.08`。由于增量有最小值 0.003，实际到达值并不只由基准曲线的终点决定。第一次答对也是 1 连击·1.05 倍，加时开始时把连击重置为 0，多巴则继承。

显示时不足 1 万取整，之后附加「万」「亿」等。单位内的数值小于 10 时保留小数第 1 位，10 以上时显示向下取整的整数。到达 100、1000、1万、10万、100万、1000万、1亿时有里程碑演出。常规游玩的数值上限不会达到兆以上。

### 5.3 连击的时限与显示

每答对一个格加 1 连击，并跨题目延续。2 连击以上才显示，20 连击以上显示「多巴×2 满级」。答错或时间到会归 0。不过在当前的实现中，1 连击的状态不参与时间到判定。

年级 `g` 的普通格时间为 `3000 + 600 × (g − 1)` ms，题目的第一个格再追加 2500ms。年级限定在 1～6，不明时按 3 处理。

| 年级 | 普通格 | 题目的第一个格 |
| --- | --- | --- |
| 1 | 3000ms | 5500ms |
| 2 | 3600ms | 6100ms |
| 3 | 4200ms | 6700ms |
| 4 | 4800ms | 7300ms |
| 5 | 5400ms | 7900ms |
| 6 | 6000ms | 8500ms |

在接受输入的时刻设定期限，题目切换与确认对话框不消耗时间。剩余时间条低于 30% 时会强调。10、20、30、50、75 连击以及 100 以上每 50 连击会有隆重的庆祝。5 连击以上中断时，会短暂显示已结束的连击数。

## 6. 出题范围与技能树

### 6.1 范围与生成

把计算划分为 58 个技能。按年级分别为 1 年级 8 个、2 年级 13 个、3 年级 14 个、4 年级 10 个、5 年级 8 个、6 年级 5 个。系别为「加减法」「乘除法」「小数·分数」「其他」4 种。全部技能的名称、标识符、前置与生成条件汇总在 `docs/curriculum.md` 中。

以四则运算、需要途中输入的竖式、小数、分数、近似数、约数与倍数、运算顺序、百分比、相等的比、求字母的值为对象。不出图形、测量、图表、应用题、汉字数字输入的题目。

每次根据技能的条件用随机数生成。利用最近 24 题的签名与该局内已出题目的签名来避免重复。候选生成设有重试上限，因此在候选较少的技能等情况下可能发生重复。时间胶囊与复习是用于重现同一题目的例外。

### 6.2 显示与解锁

每个系别拆成 2 列、共 8 列显示，窄屏时横向纵向滚动。排序以年级优先，5、6 年级放在 1～4 年级下方。前置关系的连线会避开其他节点绕行，仅排在同一列并不代表依赖关系。

没有前置的技能从一开始就解锁，前置有多个时需要全部达到大师。状态区分未获得、NEW、练习中、大师。常规的大师条件是至少有 6 题的记录，且最近 6 题中有 5 题以上首次答对。一旦达到大师的技能不会因答错而退回。水平测试的批量赋予是该次数条件的例外。

### 6.3 技能的星

达到大师后依次获得 ☆1～☆5。每一级都需要满足条件，若满足则可经同一次判定提升多级。合计最大为 290。

速度判定使用每题作答时间除以基准时间的比率。基准时间为 `第一个格的连击时间 + max(0, 作答格数 − 1) × 普通格的连击时间`。只从对象的首次答对题目中求比率的中位数。

| 星 | 条件 |
| --- | --- |
| ☆1 | 已达到大师 |
| ☆2 | 最近 20 题齐全，首次正确率 0.9 以上 |
| ☆3 | 最近 10 题齐全，其中 5 题以上首次答对，时间比率的中位数为 1 以下 |
| ☆4 | 最近 3 题全部首次答对，且各题的日期在获得 ☆3 的日期之后 7 天以上 |
| ☆5 | 最近 20 题齐全，首次正确率 0.95 以上，时间比率的中位数为 0.6 以下 |

☆4 的 3 题不限于同一天。星不会因常规游玩或休息减少，会在删除技能进度与全部重置时消失。说明画面会显示下一级星的条件、当前数值、已做题数与最短作答时间。

### 6.4 生锈

把已达到大师、且距最后一次首次答对已过 `21 × 86400000` ms 以上的技能作为候选，按从旧到新最多对 3 个显示「生锈」。若没有首次答对的日期时间，则依次参照水平测试赋予的日期时间、达到大师的日期时间。

把生锈的技能首次答对 1 题即可擦亮，保留星的同时标记消失。擦亮后，可能有其他较旧的技能成为显示对象。用于我的水平的复习与擦亮的任务。

### 6.5 技能的记录删除

对已有记录的技能长按 600ms，或在聚焦后按 Delete，即可打开确认。若从按下的位置移动超过 10px，则中止长按操作。

确认后删除该技能、以及与它直接·间接相关的技能的记录与星。所选的技能若前置仍在则回到 NEW，前置不齐则回到未获得。历史、复习、累计统计、奖杯、收藏、已通过水平测试的状态都会保留。

## 7. 持续游玩的机制

### 7.1 历史·日历·登录奖励

在基础结果保存历史，加时结束后更新同一条历史的得分、追加答对数、差一点、多巴。最多保留 3000 条。日历显示每天的最高得分与游玩次数，点击日期可以打开详情。可以移动到过去的月份，不能前往未来的月份。

连续天数以今天为起点计数，今天还没玩时则以昨天为起点。最长记录与登录贴纸的张数也会显示。游玩日与登录日不同，仅打开标题不会成为游玩日。

登录奖励按设备日期每天 1 次。按星、爱心、花、音符、四叶草、小红花、皇冠的 7 天周期领取贴纸。若中间夹有未补签的缺席日，周期会从头重新计算。贴纸在打开显示的时刻即视为已领取，关闭或重新加载也不会在同一天重复领取。

### 7.2 补签锤

1 把可以把没有游玩的 1 天补签，把游玩·登录的连续天数接上。不会把该日计入游玩天数，也不会补发缺席日的贴纸。初始持有 1 把，持有上限为 3 把。

当最后游玩日在最近 7 天以内、用持有数量能填满截至昨天的空档、并能保住 2 天以上连续时，会在标题每天提议 1 次使用。拒绝的当天不会再次提议。使用后会在日历上盖上补签的印章。使用记录最多 50 条。

### 7.3 每日任务

根据设备日期与当天选取时点的记录，确定并保存 2 个简单的与 1 个需要花些功夫的。同一天即使更改设置也不会重选。日期变化后的更新处理会切换为新的列表。候选为固定的 11 种，以及随生锈情况出现的 1 种。

| 档位 | 候选与达成条件 |
| --- | --- |
| 简单 | 通关 1 次、5 连击、首次答对 5 题、复习 1 题、NEW 的技能 1 题 |
| 需要花些功夫的 | 进入加时、加时 5 题、20 连击、通关 2 次、按年级通关 1 次、NEW 或练习中的技能 10 题、指定技能首次答对 3 题 |

没有复习·NEW 的对象时会排除相应候选。加时相关需要最近 5 条历史中有加时记录，20 连击需要 `题量 × 平均作答格数 >= 26`，练习中 10 题需要通过水平测试且存在未达到大师的候选。同一天不会叠加相同指标的多个任务。

所需时间的筛选模型按 1 局为 `(题量 × 18 + 预计进入加时时 90 + 30) / 60` 分钟计算。首次答对 5 题预计需要 `ceil(5 / (题量 × 0.7))` 次，练习中 10 题预计需要 `ceil(10 / (题量 × 0.6))` 次，20 连击预计需要 2 次。复习按最多 10 题计算，把可在模式间共同达成的项目重叠起来，选择合计 15 分钟以内的组合。这只是估算，并不限制实际所需时间。

擦亮的候选在存在生锈的日子里，若由日期生成的随机数小于 0.5、且最近 7 天内的提示次数少于 2，则成为选取对象。可以从标题开始该技能的练习，达成需要同一技能首次答对 3 题。与让生锈本身消失的 1 题条件不同。

进度在游玩中累加，达成时在画面上端提示。复习也计入共同的通关、首次答对、连击条件。3 个全部达成时，当天仅一次获得 1 把补签锤，并在日历上做标记。若已达到持有上限则只播放演出，不会把奖励留到日后。

### 7.5 与上次对比

在基础结果中，把同一技能相比以前记录有进步的地方以「有进步！」的形式最多显示 3 行。本次与对比对象双方都需要 3 题以上。对比对象为上次游玩的日子、21 天以上之前最近的一天、最初做的 3 题。不会只把同一天内过去的场次作为对比对象。

作答时间按每格的平均比较，显示为换算成本次平均格数后每题所需的秒数。把时间缩短 10% 以上、或首次正确率改善 10 个百分点以上的项目作为候选。每个技能选取最大的 1 项改善，整体按改善从大到小的顺序显示。没有改善则不显示。水平测试、演示、停止成长记录的确认用 URL 不在对象范围内。

### 7.6 时间胶囊

从每个技能保存的最初 3 题中，选取已达到大师、且距做题时点已过 `30 × 86400000` ms 以上的未使用题目中最旧的一道。

在常规的我的水平、按年级、练习的基础题组为 4 题以上时，替换从 0 开始的第 `max(1, min(N−2, floor(N/2)))` 题。水平测试、复习、加时、演示、停止成长记录的确认用 URL 不在对象范围内。每天最多 1 题，会保存预告结束时点的日期，因此之后即使中断也不会在同一天再次提示。题目完成时即视为已使用。

用信封的预告与橙色边框让人看出是过去的题目。对比时，若本次时间小于过去的 0.95 倍则显示时间缩短，否则显示答错次数减少，两者都没有则显示又一次做出来了与日期。恰好缩短 5% 时不会显示为时间缩短。

## 8. 多巴奇与演出·音效

多巴奇原则上不使用语言。造型的基准为 `docs/dopakichi.svg`。它有大大的横向耳朵、横向较宽的圆头、奶油色的脸与肚子、双层圆形的眼睛、纤细的手臂与蓝色的脚。基本颜色为粉色 `#FF97BF`、奶油色 `#FFF3E4`、耳朵内侧 `#FFE6F0`、蓝色 `#2F79F7`、轮廓 `#000000`。

输入的数字用空闲的手搬运。左右手可以分别搬运不同的数字，判定与搬运分离，不会让下一次输入等待。中途答对、最终答对使用跳跃、鼓掌、旋转等动作，答错时先散架再恢复。答错动作有 10 种，序盘 4 种、中盘 8 种、强度 0.6 以上时从 10 种中选取，并避开与上一次相同的动作。

设基础部分的题目编号从 0 开始为 `i`、题量为 `N`，则演出强度为 `E = 0.08 + 0.92 × (i/(N−1))^1.3`。只有 1 题时设 `E = 1`。加时对完成数 `k` 而言为 `tier = floor(k/3)`、`E = 1 + min(0.5, tier × 0.1)`。

按强度叠加背景、小红花等答对标记、五彩纸屑·星星·烟花·硬币、观众、行进、冲刺、彩灯、抖动。终场演出可从巨大 多巴奇、烟花大会、火箭、巡游中选择，最后显示 100 分。输入与数字键盘的布局、竖式的位对应关系保持不变。

音乐与音效由 Web Audio API 合成，不加载外部的录音素材。基础曲目为马林巴进行曲，加上 8-bit、庙会锣鼓、铜管乐队、电子乐共 5 首。使用振荡器、噪声、滤波器与混响等，逐步叠加打击乐器、低音、和弦、旋律。

基础的速度为 `112 + min(1, E) × 16` BPM，常规情况下开头为 113.28 BPM、最后为 128 BPM。最后一题会在基准基础上升高 2 个半音。加时为 `134 + tier × 5` BPM，调性在基准基础上升高 `2 + min(tier, 5)` 个半音。转调有上限，速度没有由该式决定的固定上限。

按键、数字落位、答对、答错、多巴的里程碑、时钟等用音效补足，音高与曲子的和弦同步。声音的开始使用浏览器要求的用户操作。背景使用 WebGL，不可用或上下文丢失时切换为 CSS 背景。

动效强度会反映到粒子量、抖动、闪光、背景、观众、多巴奇的大幅动作上。0% 时会停止主要的移动·抖动·闪光，说明也用静止姿势。不过这不是停止全部绘制的功能，常规画面的呼吸等与少量粒子仍会保留。操作该数值时可以在设置画面试用反应。计算的判定与得分规则不变。

Escape 用于关闭当前打开的对话框，或在标题以外打开「回到标题画面？」的确认。初始焦点为「继续」，确认期间会停止输入、基础的用时、加时与连击的期限以及每题的计时。中断前已完成题目的技能进度等会保留。若在基础结果之前，则不会创建通关记录。演示中按 Escape 即结束演示。

为按钮提供无障碍名称、焦点显示、数字以外的标签，以及说明内的焦点循环。并不保证仅用屏幕阅读器即可完成全部游玩，也不保证在所有设备上的可操作性。

高度在 700px 以下时会调整题卡·演出区域·留白，让数字键盘的最下排也能收进画面内。即使画面较矮也保持按键高度 48px。

全部重置的第 1 次以「全部重置」说明会清除的内容，第 2 次以「真的要删除吗？」确认无法恢复。两者的初始焦点都是「取消」。取消、Escape、点击背景都不会删除。第 2 次确认后，会删除所有以 `dopa-drill` 为前缀的存储键，丢弃内存中的缓存并重新加载。无关的键会保留。

初始化对象包括设置、历史、技能进度、星、成长记录、奖杯、收藏选择、贴纸、任务、道具、首次说明状态。重新启动时会重新创建首次说明与初始道具等。浏览器拒绝删除时处理也不会异常终止，但无法保证已保存的数据被清除。

## 10. 存储与隐私

保存位置为浏览器的 localStorage，键为 `dopa-drill:v1`，数据版本为 1。没有输入姓名等个人信息的栏位，应用不会把学习记录发送到服务器。没有广告、外部分析、排行榜、设备间的同步。游戏通过从分发服务器获取静态文件来运行。

当存储空间不可用、读取失败或 JSON 损坏时，会以初始状态启动；即使保存失败，也会继续当前的游戏。清除浏览器数据、存储限制、换用其他浏览器或分发来源时，记录无法继承。

| 记录 | 内容·上限 |
| --- | --- |
| 设置·说明 | 题量、声音、音量、动效、说明已显示 |
| 通关记录 | 最多 3000 条。日期、模式、得分、答对、差一点、基础用时、多巴、加时 |
| 技能 | 最近 6 题的首次答对、最近 24 个签名、最近 30 题的时间·格数·答错·日期、最近 60 天的汇总、最初的 3 题本身、最后一次首次答对·达到大师的日期时间、星 |
| 复习 | 最多 40 道题目本身 |
| 累计统计 | 完成题目·格·首次答对·答错、基础通关与模式、基础用时、最大多巴、加时、最大连击、复习、游玩天数、擦亮次数、对比·胶囊 |
| 连续·奖励 | 贴纸、登录日、补签日、补签锤、任务、已获得的奖杯、演出的选择 |

单题的作答时间从接受输入开始到最后一次正确输入为止，不含题目之间的演出与确认对话框。累计的题目·格·答错在题目完成时累加，因此中途结束的未完成题目的操作不会被统计。

对于还没有统计数据的已保存数据，会从历史中初始化可获取的数值。过去的格数、最大连击等无法从历史得知的数值从 0 开始计量。确认用 URL 并不是停止全部保存的功能。具体的差异在下一章说明。

## 11. 技术构成·运行·验证

### 11.1 文件构成

以无依赖库的 ES Modules 实现，应用无需构建。通过静态托管运行，不需要服务器端的计算处理。

### 11.2 启动与测试

在仓库根目录下，例如用以下命令即可静态托管。在显示出的服务器地址上打开 `/app/`。由于使用 ES Modules，请不要直接打开 HTML 文件，而是通过 HTTP 提供服务。

```sh
python3 -m http.server 8000 --bind 0.0.0.0
```

使用 Node.js 的测试用以下命令运行。

```sh
node --test tests/*.test.mjs
```

产品测试为 `tests/app_*.test.mjs` 的 11 个文件、58 件。上述命令还包含随附的其他测试，因此总件数会因发行版而异。在只显示文件级件数的 Node.js 环境中，在对应的环境里加上 `--experimental-test-isolation=none` 即可汇总各单项测试。

检查题目生成·输入步骤、得分、保存与重置、技能·星、出题计划、成长对比、任务、奖杯、解锁演出、说明的布局计算。自动测试通过并不能代替实机的绘制、音质、操作感验证。

### 11.3 确认用 URL 参数

像 `/app/?count=6&seed=123` 这样指定。

| 参数 | 行为 |
| --- | --- |
| `count=6`、`count=10`、`count=14` | 选择启动时的题量 |
| `seed=<数值>` | 固定用于题目选择·生成等的随机数。不固定到全部视觉效果的随机数 |
| `extra=<秒>` | 替换加时默认的 90 秒。开始时的 900ms 加算为共通 |
| `skill=<技能ID>` | 把常规的题目选择替换为该技能。与复习或固定模板并用时，选择处理有优先级 |
| `demo` | 从我的水平的入口开始固定模板的基础题组。首题为 27＋35。不进行自动操作 |
| `capture` | 收集声音事件的确认路径。抑制常规的实时音频输出与自动说明·标题奖励通知等 |

在 `skill` 与固定模板的游玩中会停止常规的作答时间·成长统计·任务，但通关记录与复习仍会保存。在 `skill` 中，若出题计划为水平测试，该计划一侧的大师赋予与测试完成的保存也会生效。奖杯判定在 `skill` 与 `capture` 下会停止，但仅指定 `demo` 不会停止。`capture` 下常规的进度·历史·统计的保存仍会继续。请不要把这些当作不留下记录的练习功能。
